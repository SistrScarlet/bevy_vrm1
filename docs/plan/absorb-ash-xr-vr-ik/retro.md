# batch-2: VR IK の VRM 知識層移管 — レトロスペクティブ

## サイクルログ

- **solver/calibration 移植**: 純粋関数の一括移植パターン (実装 + テストを丸ごと移し GREEN 確認) がそのまま機能。1 サイクルで 13 件 GREEN
- **leg IK テスト (reconstruct_ankle)**: 初回 Red が実装バグではなくテスト側の `model_flip` 二重適用 (ヘルパ内で flip するのに flip 済みオフセットを渡していた)。座標変換を含むテストヘルパは「生値を渡し、変換はヘルパ内に閉じる」規約に統一して解決
- **chest/neck なし fixture**: `parent_of` が固定の親を返すため、optional 骨を欠いた骨格で「no entry found for key」panic。存在する祖先まで遡るループで解決
- **clippy --fix の doc 自動修正**: 日本語 doc の「`model_head_y`。体長比」で backtick 範囲を壊した (句点まで含めて囲った)。--fix 後は日本語 doc 行を目視確認する

## うまくいったこと

- **調査 → 設計 → テストリストの各フェーズレビュー (サブエージェント)** が実質的な欠陥を毎回検出した: research の「歩行オフセットが第 3 の切断面」見落とし、design の foot デフォルト挙動の自己矛盾、test-list の design 明記振る舞い 3 件の欠落。いずれも実装前に 1 行レベルで修正でき、実装フェーズでの手戻りゼロ
- **移管元テストを挙動仕様として使う**: ash_xr の 12 テストが「アルゴリズム変更なし」の保証になり、移植の Green が高速だった
- **fixture の簡素化判断** (平坦 entity 群、propagation 不使用): IK システムの入力が Rest 系のみと調査段階で判明していたため、11 本の ECS テストが軽量になった

## うまくいかなかったこと

- 座標変換 (model_flip) を含むテストヘルパの引数契約を曖昧にしたまま書き、Red の原因切り分けに 1 往復要した
- clippy --fix を日本語 doc に無検査で当てて 1 箇所壊した

## 次に活かすこと

- 座標変換を含むテストヘルパは doc コメントに「引数は変換前の生値」を明記してから使う
- `clippy --fix` 適用後は差分中の日本語 doc 行を必ず目視する
- 吸収系 batch は「切断面の列挙」を research のレビュー観点に明示すると効く (今回の重大指摘は全て切断面関連)
